# Unified Codebase Analysis Report: dev-harness

**Overall Health: Fair**  
The project is a well-intentioned, functionally rich agent-orchestration CLI with solid foundational practices (good module-level docstrings, a healthy test pyramid base, and logical package separation). However, organic growth has produced dangerous **architectural debt**, **silent functional gaps**, and **missing safety nets** that threaten reliability in production use.

---

## Executive Summary

dev-harness is a Python CLI tool that orchestrates multi‑agent software development workflows (engagement lifecycle, fleet coordination, wave cycles, LLM-backed code analysis). It consists of ~20 thematic packages with a clean public interface and exemplary documentation in many modules. The test suite contains 1,826 tests, mostly unit tests, that execute in ~10 seconds.

Beneath this surface, the codebase suffers from **critical structural weaknesses**: a monolithic CLI composition root, two pairs of circular dependencies, several cross‑package coupling violations, inconsistent environment‑variable resolution, and a **phantom agent‑role bug that silently strips agents of file read/write tools during routine phases**. Error handling leans heavily on bare `except: pass`, and the test suite has zero end‑to‑end tests, leaving the primary interactive session workflow and the CLI commands almost entirely untested. File‑based state management has no concurrency control, risking data corruption in multi‑process environments. These issues combine to create a system that appears feature‑complete but is brittle, hard to maintain, and unsafe for multi‑user or concurrent operation.

---

## Cross‑Cutting Themes and Connected Findings

### 1. Phantom Agent Roles → Silent Functional Degradation
**Sources:** critical‑reviewer (phantom‑roles), code‑critic (naming), architecture‑critic (boundary violations)

The agent registry defines an `AgentRole` enum with values like `ARCHITECT`, `CODING_AGENT`, `TESTER`, etc. However, the phase definitions in `session/loop.py` and the cycle configurations in `cycle.py` use short name strings (`'researcher'`, `'coder'`, `'tester'`, `'reviewer'`) **that are not members of that enum**. When `AgentRunner._attach_repo_tool()` tries to resolve these strings using `AgentRole(agent_role_str)`, it receives a `ValueError`, which is silently caught and logged, and the RepoTool is never attached. Consequently, **all agents in the research, implementation, testing, and review phases operate without file access tools** — a critical functional gap that has gone unnoticed because no test exercises a full multi‑phase session.

**Cross‑references:**  
- Test‑auditor: 0% e2e test coverage; `session/loop.py` coverage is only 38%, so this bug escaped detection.  
- Architecture‑critic: `session/loop.py` directly depends on agent internals via `context_builder` and `pattern`, making the coupling fragile.

### 2. Inconsistent Environment‑Variable Resolution → Security & Misconfiguration Risk
**Sources:** security‑auditor, code‑critic (redundancy)

Two different env‑var substitution mechanisms exist:  
- `config/provider_models.py` uses `${VAR}` (single brace) and raises explicit errors on missing vars.  
- `session/client.py` uses `${{VAR}}` (double brace) and silently returns the literal placeholder string on missing vars.  
This means a user following the documented `${VAR}` pattern in `providers.yaml` will see their API keys treated as literal strings `"${VAR}"`, causing failed authentications and potentially exposing keys in logs. The silent fallback in `client.py` hides misconfigurations completely.

**Cross‑references:**  
- Code‑critic: duplicated resolution logic in `api_backend.py` run and run_stream.  
- Critical‑reviewer: env‑var inconsistency is a high‑risk cross‑module discrepancy.

### 3. Missing E2E Tests + Dead Test Infrastructure
**Sources:** test‑auditor, critical‑reviewer

The codebase has an elaborate but entirely unused end‑to‑end testing setup: a registered `@pytest.mark.e2e` marker, a `test-e2e` Makefile target, and README references. However, **zero tests use the e2e marker**. Running `make test-e2e` passes instantly because it runs nothing, creating a false sense of security. Meanwhile, the most critical flows — the full interactive session, engagement lifecycle execution, and the entire `cli.py` command surface — have **17% coverage** or less. This dead infrastructure misleads developers and CI systems.

**Cross‑references:**  
- Critical‑reviewer: the phantom‑role bug would be caught by a single e2e session test.  
- Architecture‑critic: cli.py is a god module, making it extremely hard to unit‑test.

### 4. Concurrency Gaps in File‑Based State
**Sources:** critical‑reviewer (concurrency‑gap, yaml‑write‑safety), security‑auditor (serialisation)

Four modules (`phase_state.py`, `lifecycle.py`, `freshness.py`, `snapshot.py`) perform load‑modify‑save on YAML files without any locking. If two harness processes (e.g., a Temporal worker and a CLI session) run concurrently, state transitions can be silently overwritten. Additionally, `yaml.dump()` is used instead of `yaml.safe_dump()` in most places, risking unparseable output or silent comment stripping.

**Cross‑references:**  
- architecture‑critic: CLI composition root directly imports Temporal infrastructure modules, making concurrent operation likely.  
- test‑auditor: no integration tests simulate concurrent access.

## Top 5 Concrete, Prioritised Recommendations

1. **Fix the phantom agent‑role bug immediately — align short names with the AgentRole enum.**  
   - Add `'researcher'`, `'coder'`, `'tester'`, `'reviewer'`, `'planner'` to the `AgentRole` enum (or introduce a name normalisation layer).  
   - Update all phase definitions in `session/loop.py` and cycle configurations to use canonical enum values.  
   - Add **at least one end‑to‑end test** that exercises a full session through all phases with a mock backend, verifying RepoTool attachment.  
   - This single fix restores basic functionality and provides a safety net.

2. **Introduce a layered architecture and eliminate the god module.**  
   - Split `cli.py` into per‑domain command modules (`cli_engagement.py`, `cli_fleet.py`, etc.) registered via a command registry.  
   - Break `session/loop.py` into orchestration, file‑block handling, system prompt building, and phase management modules.  
   - Resolve the two circular dependencies by extracting shared constants/interfaces (for loop↔interactive, move `PHASES` to a `session/_shared.py`; for runner↔cycle, define a `CycleActor` protocol).  
   - Enforce import direction with `import-linter` in CI.

3. **Standardise environment‑variable resolution on `${VAR}` with strict error‑raising.**  
   - Replace `resolve_env_vars()` in `session/client.py` with `provider_models.resolve_env_ref()`.  
   - Remove the silent fallback; raise a clear error when an env var is missing.  
   - Add a deprecation warning if the double‑brace `${{` pattern is detected.  
   - Redact API keys in `__repr__` of `Invocation` to prevent accidental logging exposure.

4. **Implement concurrency‑safe state persistence and the missing e2e test tier.**  
   - Introduce file‑level advisory locking (e.g., `fcntl.flock` or an atomic write‑and‑rename pattern) in `PhaseStateManager`, `lifecycle.py`, `freshness.py`, and `snapshot.py`.  
   - Ensure all YAML writing uses `yaml.safe_dump()` consistently.  
   - Build 3–5 e2e tests using `@pytest.mark.e2e` that cover:  
     a) `harness init` → `engagement create` → full session loop with a mock backend,  
     b) chat round‑trip,  
     c) assess/report pipeline.  
   - Fix the `test-e2e` Makefile target to fail if no e2e tests are present (use `--strict-markers` or check test count).

5. **Eliminate bare `except: pass` and raise test coverage of critical orchestration paths.**  
   - Replace every bare `except Exception: pass` with at least `logger.debug(..., exc_info=True)`.  
   - Add dedicated integration tests for `AgentRunner.run()` (36% coverage) and the main CLI commands (currently 17%).  
   - Expand `session/loop.py` tests from only pure helpers to include orchestration logic with mock SessionClient and AgentRunner.  
   - Remove or properly deprecate the `Phase1StateStore` if it is genuinely unused; if still needed, make it raise a deprecation warning on instantiation.

These five actions address the most severe functional, architectural, testing, and security gaps, moving the codebase from **fair** to **strong** and ensuring the tool can be safely used and extended.
